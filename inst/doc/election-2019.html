2019 Presidential Election: Data Preparation

Initial OCR extraction prompt

The following prompt was used to extract the 2019 election results from the uploaded PDFs into the supplied ODS template. The original wording is preserved.

“The pdf file i have uploaded contains the results of the election. Each page contains results for a electoral District. The results are in tables, where four columns exist with the column names Name of the candidate, Party Abbreviation, Votes Received, Percentage. There are 35 candidates. After the candidate results the summary is Total Valid Votes, Rejected Votes, Total Polled, Registered No of Electors as consecutive rows. These summaries also contain counts and percentages. i have uploaded an ods file with candidate names and summaries, but not the counts and percentages. Can you extract the counts and percentages and transfer it to the ods file for each electoral district, it should be one sheet for one electoral district. Can you do that ? Use OCR ?”

The same request was subsequently applied to the remaining district PDFs. Counts and percentages were extracted for all 35 candidates and the four summary rows in each result table. Subsequent validation identified the missing tables, misplaced pages, and source discrepancies documented below.

Preparation scope

This article documents the changes implemented for the 2019 presidential election. It preserves the exact capitalisation of the labels used in that script. Replacement values and source findings have not been independently verified for this documentation.

Supplemented missing results

The narrative documents adding Polling Division K — Kilinochchi, which was omitted from the 12-page Jaffna PDF. The added table contained all 35 candidates and four summary rows and became the thirteenth workbook sheet. The narrative attributes the replacement to the official Election Commission result; the supplied R code imports the completed workbook rather than downloading or performing that replacement.

Preserved registered-elector discrepancies

Printed district totals and component totals were retained and documented rather than forced to agree. Component totals include postal-vote and polling-division elector counts.

Imported and checked the ODS tables

Each sheet is read from A1:D41, excluding notes below the result table. The first sheet’s name supplies the district name. Labels are trimmed and internal whitespace condensed without lowercasing. Counts and percentages are converted to numeric values.

The code stops if a table has other than 35 candidate rows, other than four summary rows, or any missing counts. It also stops on duplicate combinations of year, district, electorate, and row label.

Aligned summary and reporting labels

Original summary label Replacement label
Total Valid Votes Total No of Valid Votes
Rejected Votes No of Rejected Votes
Total Polled Total No of Votes Polled
Registered No of Electors No of Registered Electors

District-total tables are labelled Final District Results, and postal tables are labelled Postal District Votes. Polling-division prefixes such as A - are removed, and spaces in the remaining electorate names are converted to hyphens.

ODS percentage proportions are multiplied by 100 and rounded to two decimal places, so 0.5949 becomes 59.49. This changes the storage scale, rather than recalculating a percentage from vote counts.

Validation findings and export scope

The narrative reports correcting OCR errors against scans and checking candidate totals against valid votes, valid plus rejected votes against polled votes, and component counts against district totals. Those vote-reconciliation checks are described in prose; the executable 2019 import implements structural and duplicate checks, not those arithmetic assertions.

Presence tables are constructed before and after the name mappings to support inspection across election years. They do not automatically assert that every expected label matches.
